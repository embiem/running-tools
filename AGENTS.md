# Repository Guidelines

## Project Overview

`running-tools` is a client-only Svelte 5 + TypeScript + Vite 7 SPA/installable PWA of small utilities for runners, in English, German and Spanish (Paraglide JS, see **i18n** below). Zero backend, zero runtime `dependencies` (everything is a devDependency — Paraglide compiles the messages into plain JS at build time). Seven tools are implemented: a **cadence metronome** (Web Audio), a **drink mix calculator** (pure arithmetic over literature-derived targets), a **race predictor** (equivalent performances, a pace plan and Daniels training paces from one recent result, over the Riegel and Daniels/Gilbert models), a **taper planner** (pure date and volume arithmetic over the tapering literature), **guided workouts** (a narrated warm-up and post-run stretch, played from pre-rendered voice clips), **YouTube workouts** (hand-picked follow-along warm-up, stretch/yoga and strength videos behind a click-to-load embed — the one tool that needs a connection) and a **runner's pain map** (a hand-drawn SVG body — front, back and sole — whose tappable spots list the running injuries that most often hurt there, from the running-injury literature). Home page is a bento grid of tool tiles (inline SVG icons, one headline figure each — no remote images, so it renders offline; an unfinished last row of thirds stretches its tiles to fill the row).

## Architecture & Data Flow

- **Routing**: hand-rolled hash routing in `src/App.svelte` — no router library. A `routes` map (`'/'` → `src/pages/Home.svelte`, `'/metronome'` → `src/pages/MetronomePage.svelte`, `'/drink-mix'` → `src/pages/DrinkMixPage.svelte`, `'/taper-planner'` → `src/pages/TaperPlannerPage.svelte`, `'/race-predictor'` → `src/pages/RacePredictorPage.svelte`, `'/workouts'` → `src/pages/WorkoutsPage.svelte`, `'/youtube-workouts'` → `src/pages/YouTubeWorkoutsPage.svelte`, `'/pain-map'` → `src/pages/PainMapPage.svelte`), `location.hash` read + `hashchange` listener, unknown routes fall back to `/`. `App.svelte` also renders the sticky top bar (brand + tool nav + language picker; the nav is hidden below 52rem and icon-only below 70rem — the width the German and Spanish labels need beside the picker — its labels kept for screen readers, so seven tools fit) and wraps every page in the `.shell` content column. `PWABadge` is mounted once, in `App.svelte` — do not mount it again in a page.
  - Rationale (documented in `App.svelte` comments): hash routes work from the precached service-worker shell with no server rewrite config → every route works fully offline. **Do not introduce path-based routing or SvelteKit.**
- **i18n**: Paraglide JS (`@inlang/paraglide-js`, the i18n add-on of the Svelte CLI). All user-visible copy lives in `messages/{en,de,es}.json` (flat keys, prefixed by area: `app_`, `home_`, `tool_`, `drink_`, `race_`, `taper_`, `workout_`/`workouts_`, `yt_`, `pain_`, `common_`, `unit_`, `distance_`); `en.json` is the source. `project.inlang/settings.json` loads the message-format plugin from `node_modules` (not the CDN URL Paraglide's docs use), so builds work offline. The Vite plugin (and `npm run i18n` outside Vite) compiles them into typed functions in `src/paraglide/` — generated, self-gitignored, excluded from the tsconfig root set — used as `import { m } from '../paraglide/messages.js'` → `m.drink_result_title({ ml })`; a missing key or parameter is a type error. `src/lib/i18n.svelte.ts` owns the language: it resolves the first locale itself (a saved choice under Paraglide's `localStorageKey`, then `navigator.languages` via Paraglide's `extractLocaleFromNavigator` — de-AT → de, es-MX → es — then English; not Paraglide's `getLocale()`, which would save the detected language as if picked), holds it in a `$state` rune, points Paraglide's `getLocale()` at that rune with `overwriteGetLocale`, and sets `<html lang>`. So `setLanguage()` (the top-bar `<select>`) re-renders every message in place — no reload, a running metronome or workout keeps going. Data modules hold messages as `Message` refs (`name: m.tool_metronome_name`) and templates call them (`tool.name()`), so nothing is resolved at import time; the tool engines build their labels and flag messages with `m.*` too, which makes their output follow the language inside the `$derived` chain. Numbers and dates go through `src/lib/format.ts`: `formatFixed`/`formatDecimal` (`toFixed`/`String` semantics with the locale's decimal mark — English stays byte-identical), `formatPercent` ("12%" / "12 %"), `dateLocale()` (the browser's regional variant of the app language, e.g. en-GB). The few messages with inline markup (`<strong>`, `<em>`, `<sup>` in the "where these numbers come from" sections) render with `{@html}` — trusted copy, never user input. `npm run check` runs `scripts/check-messages.mjs`, which fails unless de/es carry exactly the English keys, `{placeholders}` and HTML tags (Paraglide itself silently falls back to English). German and Spanish address the reader informally (du / tú), use decimal commas, a no-break space before `%`, and soft hyphens (U+00AD) in long words of the display-sized titles so they break on phones.
- **Metronome**: framework-free engine in `src/lib/metronome.ts` (Web Audio "lookahead scheduler": 25 ms `setInterval` polls, schedules clicks up to 120 ms ahead on the audio clock — sample-accurate, throttling-immune). Exported as a **module-level singleton** `export const metronome = new Metronome()`; one engine per app must survive route changes.
- **UI ↔ engine contract**: `src/lib/Metronome.svelte` binds to the singleton, mirrors `metronome.running` into local `$state` on mount, and two `$effect`s are the single source of truth pushing `bpm` → `metronome.bpm` + `localStorage` (`metronome.bpm`) and `volume` → `metronome.volume` + `localStorage` (`metronome.volume`, 0–1, engine default 0.5). The engine's scheduler reads `volume` on every poll as the tick's peak gain, so a muted tick (0) is simply not scheduled — exponential ramps need a nonzero start. Never instantiate `Metronome` in components.
- **Drink mix**: stateless pure functions in `src/lib/drinkMix.ts` — no class, no singleton, no DOM. `computeMix(input)` returns the recipe (grams of table salt / potassium chloride / sugar), what the batch delivers (sodium, potassium, carbohydrate, kcal, osmolality → tonicity), coverage of the session plan and the advice flags. `normalizeMixInput` turns any raw value into a valid `MixInput`; `isCompleteMixInput` reports whether every field is filled. Preset targets and concentration caps are derived from the ACSM / joint position-stand literature cited in the module header — **not** from commercial drink formulations.
- **Race predictor**: stateless pure functions in `src/lib/racePredictor.ts` — same shape as the drink mix engine. `predictRace(input, today?)` turns one recent result into a VDOT fitness score, then returns equivalent performances at every standard distance from two independent models (Riegel's `T₂ = T₁ × (D₂/D₁)^1.06` and Daniels/Gilbert's VO₂ ÷ %VO₂max, bisected on the duration it is solving for), the training-pace bands that VDOT implies (Daniels' 59–74 / 75–84 / 83–88 / 97–100 / 105–110 % bands, each paced by inverting the VO₂ quadratic), the goal race's split plan (even, or a linear ramp whose second half averages 1.5% faster — run at the models' predicted pace or at the runner's own `goalPaceSecPerKm` override) and the advice flags. `normalizeRaceInput` validates anything raw (the `mm:ss` / `h:mm:ss` time string included) into a `RaceInput`; `isCompleteRaceInput` gates persistence; `parseDuration` / `formatDuration` / `parsePace` / `formatPaceClock` / `formatPace` / `formatPaceRange` / `formatDistance` are shared with the UI. The module header cites what is literature and what is layout.
- **Taper planner**: stateless pure functions in `src/lib/taperPlanner.ts` — same shape as the drink mix engine. `predictTaper(input, today?)` counts the taper back from race day: the weekly training volume decays geometrically (bisection-solved so the taper window lands 50% below the same number of normal weeks, the middle of the 41–60% band Bosquet 2007 found optimal), then each week's volume is split over its runs and rounded to something runnable (largest remainders, so a week's days add up to the week's target instead of drifting above it). It returns the week and day schedules plus the realized volume reduction and the advice flags. `normalizeTaperInput` validates anything raw (dates included) into a `TaperInput`; `isCompleteTaperInput` gates persistence; `formatDistance`/`todayISO` are shared with the UI. Session *types* (long run, sharpener, day-before strides, rest two days out) are documented convention, not measurement — the module header says which parts are literature and which are layout. The defaults (a 40 km / 25 mi week, 4 runs a week) and the volume thresholds come from the 158,117 recreational marathoners in Smyth & Lawlor 2021, cited in the header.
- **Guided workouts**: session data in `src/lib/workouts.ts` (steps with name, spoken description, duration, optional halfway cue; the module header cites what is literature and what is layout), plus `cues`/`narrationLines` — every sentence the player can say. Playback is a class + module-level singleton in `src/lib/workoutPlayer.ts` (`workoutPlayer`, survives route changes like the metronome): a 250 ms wall-clock timer that announces each step, its halfway cue and a 3-second countdown to the next. **Narration is pre-rendered and English only** (the on-screen titles, step names and descriptions are `workout_*` messages and follow the app language; `cues`/`narrationLines` build every spoken sentence from their English version, `{ locale: 'en' }`, plus the speech-only `halfwayCue` strings): `npm run narrate` (`scripts/generate-narration.mjs`, Kokoro-82M via `kokoro-js` + ffmpeg, voice `af_bella`) renders each `narrationLines` sentence to a content-addressed MP3 in `src/assets/narration/` and maps sentence text → file in `manifest.json` there. The player bundles clips via `import.meta.glob` (Vite-hashed under `/assets/`, precached by the SW — the workbox `globPatterns` include `mp3`), resumes its own `AudioContext` inside the Play click, decodes the session's clips up front and queues them back to back on the audio clock. **Any English wording change to a step (in `workouts.ts` or its `workout_*` keys in `messages/en.json`) needs `npm run narrate`** and the regenerated clips committed; a sentence missing from the manifest is skipped with a console warning.
- **YouTube workouts**: curated data in `src/lib/youtubeWorkouts.ts` (`VIDEO_GROUPS`, `YOUTUBE_WORKOUTS`: video id, title, channel, category, stated length, one-line `why`; titles and channels are the videos' own and stay in English, as do the videos — the German and Spanish copy says so; the module header gives the selection criteria — not view counts alone). `src/lib/YouTubeEmbed.svelte` is a hand-rolled click-to-load facade (no library: the Svelte packages either need a newer Svelte or ship a web component with their own CSS): a lazy `i.ytimg.com` thumbnail plus a play button, swapped on click for a `youtube-nocookie.com` iframe with `autoplay=1`, so nothing loads from YouTube until the viewer presses play. `src/lib/YouTubeWorkouts.svelte` renders the groups and shows an offline notice from `online`/`offline` events. Do not set `referrerpolicy="no-referrer"` on the iframe (or tighten the Caddyfile's `Referrer-Policy`): YouTube refuses embeds that send no referrer.
- **Pain map**: static data in `src/lib/painMap.ts` — the wording is in the message catalog (`pain_cause_<cause id>_<field>`, `pain_spot_<spot id>_<field>`, views, red flags), the module keeps the structure — `CAUSES` (per injury: name, `aka`, `likelihood`, `care` = `self`/`doctor`/`urgent`, optional literature `stat`, and the `feels`/`why`/`helps`/`check` copy), `SPOTS` (the 25 tappable spots: name, `where`, the `views` it appears in — first is its home view — `causes` commonest first, and `nearby` spots offered after a mis-tap; a compile-time check fails the typecheck if a `nearby` id is not a real spot), `TOP_INJURIES`, `RED_FLAGS`, and `normalizeSelection` for the persisted `{ view, spot }`. The module header cites the source of every figure and description (Kakouris 2021 for the injury shares) and says what is layout. The drawings are geometry in `src/lib/bodyMap.ts`: one 200 × 490 frame for all three views, outlines as right-half point lists mirrored across the centre line and smoothed with a Catmull-Rom spline, and zone ellipses (`pair: true` mirrors a zone onto the other limb; one copy per spot takes keyboard focus). `src/lib/BodyMap.svelte` renders a view (an outline pass under a fill pass so overlapping parts merge into one silhouette; dots that pulse until a spot is picked; a label that follows mouse hover and keyboard focus, then stays pinned on the selection) and `src/lib/PainMap.svelte` is the tool UI, persisting `painMap.selection`. Hotspot colour is `--danger`, not the volt accent: red reads as "pain here".
- **PWA**: `vite-plugin-pwa` with `registerType: 'prompt'`, `injectRegister: false` — SW registration is manual via `src/lib/PWABadge.svelte` (`virtual:pwa-register/svelte`). PWA icons are generated at build time from `public/favicon.svg` via `pwa-assets.config.ts` (`minimal2023Preset`), emitted into `dist/`.
- **Deployment**: production (`https://run.embiem.me`) is built and served by Coolify via Railpack's Node provider (Caddy web server), which auto-detects the `vite build` script and serves `dist/`. Railpack lets a project override its generated Caddyfile with one at the project root — `Caddyfile` does that: `Cache-Control: no-cache` on everything unhashed (`index.html`, `manifest.webmanifest`, `sw.js`, icons) so a reload after a deploy always re-fetches an `index.html` that references asset hashes still on disk, `public, max-age=31536000, immutable` on `/assets/*` (Vite's content-hashed bundle) gated on the file actually existing (never cache a 404), and **no** `index_fallback` — this app is hash-routed, so there is no server-side path to fall back for, and an unmatched request (e.g. a hash deleted by the next deploy) correctly 404s instead of masquerading as `index.html` with the wrong MIME type (which is what silently produced a blank page on refresh before this file existed). Validate changes with `caddy validate`/`caddy run` against a built `dist/` (see git history for the exact commands), not by editing Coolify's generated config directly — it gets regenerated from this file on every deploy.
- **Data flow**: user input → Svelte runes state → engine mutation / `localStorage` → Web Audio scheduling. No network calls, no stores beyond Svelte built-ins. The drink mix, race predictor and taper planner tools are the same shape without audio: `input` → `$derived(normalize…Input(input))` → `$derived(computeMix(…) / predictRace(…) / predictTaper(…))`, so one validated snapshot feeds every figure on the page. The race predictor and taper planner additionally derive their flags from today's date, passed in rather than read inside the maths. The pain map has no maths: a picked spot indexes static data. The language is one more rune (`i18n.svelte.ts`) that every message reads, so switching it re-runs exactly the templates and `$derived`s that show copy.

## Key Directories

- `messages/` — `en.json` (source), `de.json`, `es.json`: every user-visible string, as Paraglide/inlang message files. Add a key to all three.
- `project.inlang/` — Paraglide project settings (`settings.json`; the rest of the folder is inlang's own, self-gitignored).
- `src/paraglide/` — generated by Paraglide (Vite plugin / `npm run i18n`), self-gitignored. Never edit.
- `src/pages/` — route-level pages (Home bento grid; MetronomePage, DrinkMixPage, RacePredictorPage, TaperPlannerPage, WorkoutsPage, YouTubeWorkoutsPage and PainMapPage are one-line `<ToolPage route=…>` wrappers).
- `src/lib/` — reusable components and logic (`metronome.ts` engine, `Metronome.svelte` UI, `drinkMix.ts` engine, `DrinkMix.svelte` UI, `racePredictor.ts` engine, `RacePredictor.svelte` UI, `taperPlanner.ts` engine, `TaperPlanner.svelte` UI, `workouts.ts` session data + spoken cues, `workoutPlayer.ts` playback engine, `WorkoutPlayer.svelte` UI, `youtubeWorkouts.ts` curated video list, `YouTubeEmbed.svelte` click-to-load embed, `YouTubeWorkouts.svelte` UI, `painMap.ts` pain map data, `bodyMap.ts` body drawing geometry, `BodyMap.svelte` interactive body SVG, `PainMap.svelte` UI, `flags.ts` shared advice-flag type, `i18n.svelte.ts` language state + `Message` type, `format.ts` locale-aware number/date formatting, `tools.ts` tool registry (name, route, icon, description), `ToolPage.svelte` tool page header/layout, `Icon.svelte` inline SVG icon set, `Panel.svelte` shared input panel, `PWABadge.svelte` update toast).
- `src/assets/narration/` — generated by `npm run narrate`, committed: workout narration MP3s (named by content hash) + `manifest.json` (sentence text → clip). Never hand-edit.
- `scripts/` — dev-only Node scripts (`generate-narration.mjs`, `check-messages.mjs`); not part of the build.
- `public/` — static assets copied verbatim to `dist/` (only `favicon.svg`).
- `dist/` — gitignored build output; deployable artifact for any static host (root-path deploy: no `base` set, SW scope `/`).

## Development Commands

```bash
npm run dev       # vite dev server
npm run build     # vite build (also generates PWA assets + sw.js)
npm run preview   # serve dist/
npm run check     # npm run i18n + scripts/check-messages.mjs (de/es match en) + svelte-check + tsc -p tsconfig.node.json
npm run i18n      # compile messages/ into src/paraglide without Vite (check and narrate run it first)
npm run narrate   # re-render workout narration clips (Node ≥ 22.18, ffmpeg with libmp3lame; --dry-run, --force, --voice=, --speed=, --device=cuda)
```

There is **no** test, lint, or format script. `npm run check` is the only quality gate — run it before delivering changes.

## Code Conventions & Common Patterns

- **Svelte 5 runes everywhere**: `$state`, `$derived`, `$effect`; `mount()` bootstrap in `src/main.ts`. No legacy stores (exception: `PWABadge.svelte` consumes the plugin's generated store wrapped in `$derived`).
- **Engine/UI separation**: platform logic lives in plain TS (`src/lib/*.ts`) — a class plus module-level singleton when state must survive navigation (`metronome.ts`), pure functions when it must not (`drinkMix.ts`, `taperPlanner.ts`); `.svelte` files are thin bindings with scoped `<style>` blocks. Follow this split for new tools.
- **Private class fields** (`#ctx`, `#timer`) for engine internals; public surface kept minimal (`bpm`, `volume`, `running` getter, `start()`/`stop()`).
- **TypeScript strict** (`@tsconfig/svelte` → strict, `verbatimModuleSyntax`; ES2022; `allowJs`/`checkJs` on for `src/`). Use `interface`/types for data shapes (see `Tool` in `Home.svelte`).
- **State persistence**: validated `localStorage` read + write in the same `$effect` that drives the engine (see `STORAGE_KEY` pattern in `Metronome.svelte`). Where a bound form can be transiently incomplete, gate the write on completeness (`isCompleteMixInput`, `isCompleteRaceInput`, `isCompleteTaperInput`) so a half-typed field cannot persist a fallback over the last good value (`DrinkMix.svelte`, `RacePredictor.svelte`, `TaperPlanner.svelte`).
- **Copy is always a message**: never hard-code user-visible text (labels, aria-labels, titles, flags, units that differ by language such as "tsp") in a component or engine — add a key to `messages/en.json`, `de.json` and `es.json` and use `m.<key>()`. Keep parameters as preformatted strings where a number needs a decimal mark or a percent sign (`formatFixed`, `formatPercent`); integers can go in as numbers. Data that must stay reactive holds `Message` refs, not resolved strings.
- **Accessibility**: aria-labels on controls (`aria-label="Cadence in steps per minute"`), `role="alert"` toast, semantic `<details>` for info copy. Keep this up.
- **Styling** ("performance dark"): global `src/app.css` holds the design tokens on `:root` (`--bg #0b0b0f`, `--surface`, `--surface-2`, `--border`, `--text`, `--muted`, volt `--accent #d4ff3a` + `--on-accent` for text on it, `--accent-text` for accent-coloured *text* — darkened in light mode, since volt is unreadable on white — `--danger`, `--ok`, radii, shadow), redefined once under `prefers-color-scheme: light`. **Never hard-code a colour in a component; use the tokens.** It also holds the shared tool vocabulary every tool uses: `.tool` / `.tool.split` (two columns ≥ 60rem: `.inputs` sticky left, `.results` right) / `.tool.narrow`, `.fields` / `.label-text` / `.label-input` / `.unit` / `.hint`, `.segmented` (radio groups as pill segmented controls — the native radio stays in the DOM, visually hidden), `.stats` / `.stat` / `.stat.hero` (headline number tiles), `dl`/table styling, `tr.highlight`, `.flags`/`.flag`, `.info` details, `button.primary`/`button.ghost`, range sliders (set `--fill` inline for the WebKit track fill). Components keep only what is specific to them in scoped styles. No CSS framework.
- **Typography**: Archivo variable (`@fontsource-variable/archivo`, devDependency), latin `wdth` subset only, declared by hand in `app.css` and bundled + precached (workbox `globPatterns` include `woff2`). Body text at normal width; `.display` (and `.stat-value`) use `font-stretch: 75%` + weight 800 for condensed titles and oversized numerals.
- **Input panels**: each group of inputs renders through `src/lib/Panel.svelte` (`<Panel title="…" hint="…">`), which owns the border, tint, heading and hint. Results are left unboxed (bar the headline `.stat` tiles), so a panel always means "you set this". A tool's root is `<section class="tool …">` carrying the layout — `Panel` renders a `<section>` and an `h2` too, so keep layout rules on `.tool` and results headings on `.results > h2`, never on bare `section`/`h2` selectors.
- **Browser-only APIs assumed**: `AudioContext`, `localStorage`, `location.hash`, `navigator.languages`. Never add Node-dependent code to `src/`.
- **Safari note**: `AudioContext` constructor typed without `latencyHint` but supports it at runtime — keep the cast/workaround comment in `metronome.ts`.

## Runtime/Tooling Preferences

- **Package manager**: npm (only `package-lock.json` exists). Node ≥ 20.19 / 22.12 / 24 (Vite 7 requirement); no `engines` field is declared.
- **ESM everywhere** (`"type": "module"`); module scripts, no CommonJS.
- `overrides` pin `sharp`/`sharp-ico` — don't bump them casually (asset generation).
- Deployment target is **root path** (`start_url`/`scope` = `/`). A subpath host would need a Vite `base` change plus SW scope review.

## Testing & QA

- **No test framework, test files, CI, linter, or formatter exist.** No `.github/`, no git hooks, no eslint/prettier config.
